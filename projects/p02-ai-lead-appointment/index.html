01 / The business problem

A booked calendar is not enough.
The CRM must tell the same story.

A lead can receive a useful AI answer while the actual revenue process loses the handoff. These are the failure modes the implementation was designed to examine.

Failure risk 01

Qualified in chat. Missing in CRM.

If qualification never triggers the correct CRM actions, the sales team inherits an incomplete or invisible lead.

Failure risk 02

Booked twice. Tracked twice.

Duplicate opportunities and contact mismatches can fragment ownership, reporting and follow-up.

Failure risk 03

Booking changed. Pipeline didn't.

Rebooking, cancellations and invalid stage transitions can leave the opportunity in the wrong operational state.

✓
The engineering objective: preserve identity, validate each transition and leave evidence.

HighLevel is the system of record. The test focuses on the original contact and opportunity, not merely an AI conversation or calendar confirmation.

03 / Execution evidence

Eight tests. Eight documented passes.
Including the failure path.

Results were checked against HighLevel execution logs, appointment states, contact tags and opportunity readbacks on 17–18 November 2026. Each result applies to its described scenario.

PASS
Eligible enquiry

AI action applied the qualified tag and created an Open opportunity in Estimates / Qualified.

PASS
Repeat enquiry, same chat

The original opportunity ID was preserved; no second opportunity appeared for the tested contact.

PASS
Out-of-scope enquiry

A commercial exterior request from Cork produced no qualification tag, new opportunity or automated booking link.

PASS
Confirmed API booking

The existing Open opportunity advanced from Qualified to Booked.

PASS
Public calendar form

Normal browser submission matched the known-email contact and avoided creating another opportunity.

PASS
Rebooking after repair

An observed HTTP 400 backward-stage error was corrected through stage-order configuration; the same opportunity reached Booked on retest.

PASS
Cancellation event

The published, filtered workflow generated an assigned review task without blindly changing opportunity stage.

PASS
Human-reviewed cancellation

All seven QA appointments were cancelled; a reviewer changed the same opportunity to Reschedule Needed and completed the task.

Why the failed execution matters: one real run returned “Moving an opportunity backward in the pipeline is not allowed.” The stage order was changed to New → Qualified → Reschedule Needed → Booked → Needs Review while preserving the existing record IDs. A subsequent rebooking test passed. Failure and correction are both retained in the technical case study.

04 / Decisions behind the build

Built for a reliable handoff.
Not for a prettier workflow diagram.

The controls below explain which transitions were automated, what was verified, and where a human decision is intentionally required.

Automation path

Qualification → booked

  1. AI chat checks residential interior painting, Dublin location and buying intent.
  2. Qualification action tags the matching CRM contact.
  3. Opportunity workflow creates the qualified estimate opportunity.
  4. Confirmed appointment finds and updates the existing Open opportunity.
Controlled human review

Cancelled → reschedule

  1. Cancellation event triggers a calendar- and test-tag-filtered workflow.
  2. Find Opportunity locates the existing Booked opportunity.
  3. Assigned task asks a reviewer to check other future confirmed appointments.
  4. Human decision moves the same opportunity to Reschedule Needed only when appropriate.
